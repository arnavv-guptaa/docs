The **Parallax API** gives you programmatic access to Chicago Global's investment
intelligence: multi-factor scoring, portfolio analysis and tracking, financial
statements, analyst estimates, ETF analytics, valuation (DCF & multiples), macro
and market telemetry, and AI-generated research reports.

## Base URL

All API requests should be made to:

```
https://api.chicago.global
```

The current API version is **v1.1.0**. The URL path version (`/v1/`) is a separate,
slower-moving axis — see the [changelog](https://github.com/arnavv-guptaa/parallax-api/blob/main/CHANGELOG.md)
for the release history and our SemVer policy.

## Authentication

All `/v1/*` endpoints require a Bearer token in the `Authorization` header:

```bash
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Keep your API key secure. Do not expose it in client-side code or public repositories.
Contact [parallax@chicago.global](mailto:parallax@chicago.global) to request a key.
</Warning>

<Tip>
Prefer using the tools directly from an AI client? The same intelligence is available
over the **[Parallax MCP server](/mcp/overview)** with browser-based OAuth sign-in
and client-managed access tokens.
</Tip>

## Symbol format

Most endpoints accept a symbol in **RIC** format — the ticker plus an exchange suffix,
e.g. `AAPL.O` (Apple, Nasdaq), `JPM.N` (JPMorgan, NYSE), `RELI.NS` (Reliance, NSE),
`2330.TW` (TSMC, Taiwan). Plain tickers are accepted by some endpoints and by
`/v1/validate-symbol`, but RIC is the canonical form. Use
[Stock Search](/api-reference/stock/search) or
[Validate Symbol](/api-reference/validation/validate-symbol) to resolve a RIC.

## Async job processing

Long-running endpoints (portfolio analysis, stock reports, technical/financial/news
analysis, CIO reports, assessments, company background, macro context) use an async
job pattern:

1. **Submit** — `POST` your request to the endpoint.
2. **Receive a job** — you get a `job_id` (and a polling URL) immediately.
3. **Poll** — `GET /v1/jobs/{job_id}` until `status` is `completed` (or `failed`).
4. **Read results** — the completed response contains your data.

```javascript
// 1. Submit
const { job_id } = await fetch('https://api.chicago.global/v1/portfolio/analyze', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${API_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify(payload),
}).then(r => r.json());

// 2. Poll
let result;
while (!result) {
  const status = await fetch(`https://api.chicago.global/v1/jobs/${job_id}`, {
    headers: { 'Authorization': `Bearer ${API_KEY}` },
  }).then(r => r.json());

  if (status.status === 'completed') result = status.result;
  else if (status.status === 'failed') throw new Error(status.error);
  else await new Promise(r => setTimeout(r, 3000));
}
```

Use [List Jobs](/api-reference/jobs/list) to enumerate recent jobs, and
[Get Job Status](/api-reference/jobs/status) to poll a single job.

## Response headers

| Header | Description |
|--------|-------------|
| `X-Request-ID` | Unique ID for the request. Include it when reporting an issue so we can trace it. |
| `X-Credits-Remaining` | Your organization's remaining credits, when available. The value can be fractional, such as `99.95`. |

## Credits

Requests use your organization's credit balance. Prices can be fractional.
For endpoints priced per symbol, a comma-separated list costs the price multiplied
by the number of submitted symbols. For example, `company-info?symbol=AAPL,MSFT`
costs `0.1` credits.

| Endpoints | Credits |
|-----------|---------|
| Company info, income statement, balance sheet, cash flow, key ratios, daily price, financial summary, dividend history, dividend-yield history, current ratios | 0.05 per symbol |
| Analyst targets, recommendations, upgrades and downgrades, earnings and revenue estimates, earnings history, EPS trends and revisions | 0.05 per call |
| News, peers, rolling volatility and drawdown, historical scores, score metrics, returns calendar, sector scores, Altman Z-Score, Piotroski F-Score, risk-return profile, DCF, multiples | 0.1 per call |
| ETF profile, scores, holdings, and other ETF analytics | 0.1 per call |
| ETF daily price | 0.05 per symbol |
| Telemetry endpoints | 0.05 per call |
| Stock and ETF search, symbol validation, job listing and polling, macro-report markets | Free |
| Portfolio analysis, portfolio report, Builder, financial, technical, score, news, and peers analysis, company background, macro context | 5 per job |
| Stock report, CIO report | 10 per job |
| Assessment | 5 for `fast` or `default`; 10 for `deep` |
| Macro report | 5 per call |
| Portfolio tracker summary and analytics | 1 per call |
| Other portfolio tracker endpoints | Free |

Billable reads check your balance before processing and deduct credits after a
successful response. Failed HTTP requests do not deduct credits. Background jobs
deduct credits when they complete successfully. Job polling is free.

An insufficient balance returns HTTP `402`:

```json
{
  "detail": {
    "error": "Insufficient credits",
    "balance": 0.02,
    "required": 0.05,
    "endpoint": "/v1/company-info"
  }
}
```

Both `balance` and `required` are numbers that can be fractional. Parse them and
`X-Credits-Remaining` as decimal values, not integers.

## Data availability

Market-data reads use a Postgres mirror. Data age does not cause a request to be
refused. HTTP `503` indicates a service or data availability failure.
The [health check](/api-reference/health) reports `healthy` or `unhealthy`.

<Warning>
As of October 19, 2026, `GET /v1/macro` and
`GET /v1/macro/markets/{market}` return HTTP `500` in production and are
unavailable. These are separate from the [Macro Report](/api-reference/macro/report)
and [List Macro Markets](/api-reference/macro/markets) endpoints.
</Warning>

## Response codes

| Code | Description |
|------|-------------|
| 200 | Success |
| 202 | Background job accepted; poll its `check_url` |
| 400 | Invalid input, including an unrecognized symbol |
| 401 | Unauthorized — invalid or missing API key |
| 402 | Insufficient credits; `detail.balance` and `detail.required` can be fractional |
| 404 | Not found |
| 422 | Validation error — check the request body |
| 429 | Rate limit exceeded — slow down and retry |
| 500 | Server error — includes an `X-Request-ID` you can report |
| 503 | Service or data unavailable; data age alone does not cause this response |

## Rate limits

Requests are rate limited per API key. If you exceed your limit you'll receive a
`429` response. Respect `Retry-After` before retrying. The
`X-RateLimit-Limit` and `X-RateLimit-Remaining` headers show the applicable
request limit and remaining requests.
